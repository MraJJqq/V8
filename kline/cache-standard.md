# 全历史持久化缓存原则

本规范是 VEGAS 素材库 K 线系统的统一缓存标准。缓存策略与图表显示、手势、EMA 绘制、品种轮播相互独立。

## 1. 历史范围
- 每个品种、每个周期，尽可能获取行情源实际提供的全部历史 K 线。
- 不设置固定年限、固定根数或人为截断上限。
- 交易所接口分页到达可探测的历史边界后，记录为“接口历史边界已探测”；不得把请求失败、限流或分页异常当作历史结束。
- 指标所需的最少历史数量只用于判断指标是否可用，不是缓存上限。

## 2. 持久化与隔离
- 使用 IndexedDB 持久化 K 线；每根 K 线独立存储，元数据独立保存，避免每次更新都重写整份历史数组。
- 旧版整组数组缓存通过数据库版本升级按品种/周期惰性迁移，不删除历史 K 线。
- 缓存键必须由“交易所/数据源 + 品种 + 周期”组成；不同周期、不同数据源不得共用同一条缓存记录。
- 记录数据条数、最早/最新时间、最后更新时间、历史边界状态和缓存结构版本。
- 内存备用缓存设单序列 12,000 根、全局 30,000 根及最多 8 个序列的限制；达到上限时明确标记临时截断，不得标记历史完整。
- 监控浏览器存储使用率，达到 80%/90% 发出警告/严重告警；不自动删除持久历史。
- 写入前按 K 线时间戳去重并升序排列；保留交易所原始 OHLC 数据，不人为偏移或合成价格。

## 3. 加载与更新顺序
1. 先读取本地持久缓存并立即供图表使用。
2. 再请求最新行情，合并新增 K 线。
3. 检测缓存末端与最新行情之间是否存在时间缺口；存在则分页补齐，不能只追加最新几根而留下断层。
4. 从最早缓存时间继续向前分页，直到探测到接口历史边界。
5. 只写入新增或修正后的数据，不反复全量下载已有历史。

## 4. 补齐任务
- 历史补齐队列与当前选中品种、轮播、图表重绘和手势生命周期解耦。
- 每个品种/周期独立保存补齐进度；一个任务失败不得阻断其他品种。
- 页面隐藏或关闭时，浏览器请求可能暂停；恢复或重新打开后从 IndexedDB 已保存的位置续传。
- 对限流、网络失败、超时和分页停滞进行区分；失败不得写入“已完成”状态。
- 控制并发和请求频率，避免大量品种同时请求。

## 5. 完整性状态
每个品种/周期至少记录：
- 历史最早时间、最新时间、缓存条数；
- 向前历史是否已探测到接口边界；
- 最新端是否存在缺口；
- 最近一次请求结果及失败原因；
- 缓存结构版本。

只有历史端与最新端均无未解决缺口，且历史分页已探测到接口边界，才可标记为完整。该状态表示“按当前接口分页规则已探测到边界”，不宣称交易所绝对不存在更早数据。

## 6. V6 Gate 实现范围
- 数据源为 Gate USDT 永续合约 REST K线与 `futures.candlesticks` WebSocket。
- 控制器支持 1H、2H、4H、8H、1D；每个周期独立缓存、独立续传、独立记录历史边界。2H 由 Gate 1H K 线按时间桶聚合生成，不直接请求 2H 接口。
- IndexedDB 缓存键为 `Gate USDT + contract + timeframe`，不同品种、不同周期绝不共用缓存记录。
- 27 个品种 × 1H、2H、4H、8H、1D 的历史补齐由独立队列逐项执行，与当前选中品种、轮播、图表重绘和手势生命周期解耦；其中 2H 使用 1H 数据聚合。
- 页面隐藏后暂停；恢复后从 IndexedDB 已保存的位置续传，不因品种切换而取消历史任务。
- 实时更新使用 Gate WebSocket；REST 用于初始加载、历史分页和恢复后的校准。
- 本规范不授权改变图表视觉、EMA 参数、手势和视窗交互。
